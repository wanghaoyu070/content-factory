# API 错误码对照表

这个表给前端和联调使用，目标是让错误提示统一、可理解、可操作。

## 处理原则
- `4xx`：用户输入或权限问题，优先提示用户修正。
- `5xx`：系统或上游问题，提示稍后重试，并记录 `requestId`。
- 返回体里有 `requestId` 时，错误弹窗建议附带该值，便于后端排查。

## 错误码映射
| code | HTTP | 含义（通俗） | 前端建议提示 | 是否建议重试 |
|---|---:|---|---|---|
| `BAD_REQUEST` | 400 | 你提交的参数不对 | 请检查输入后重试 | 否 |
| `UNAUTHORIZED` | 401 | 没登录或登录失效 | 请先登录 | 否 |
| `FORBIDDEN` | 403 | 登录了但没权限 | 当前账号无权限 | 否 |
| `NOT_FOUND` | 404 | 资源不存在 | 数据不存在或已删除 | 否 |
| `UNPROCESSABLE_ENTITY` | 422 | 参数格式对，但业务不允许 | 当前操作不符合规则 | 否 |
| `UPSTREAM_TIMEOUT` | 504 | 第三方接口超时 | 服务响应慢，请稍后再试 | 是 |
| `UPSTREAM_ERROR` | 502 | 第三方接口报错 | 上游服务异常，请稍后再试 | 是 |
| `SERVICE_UNAVAILABLE` | 503 | 相关服务未配置或不可用 | 服务暂不可用，请联系管理员 | 视情况 |
| `INTERNAL_ERROR` | 500 | 系统内部异常 | 系统异常，请稍后重试 | 是 |

## 前端落地建议
- Toast 文案优先用后端返回的 `error`。
- 若有 `code`，可附加一行简短说明（例如 “请求超时，可稍后重试”）。
- 若有 `requestId`，在“复制错误信息”按钮里带上，便于排查。
